# Gemma 4 Metal and forced-streaming baseline

This is a local correctness/performance observation, not a universal hardware
claim.

## Conditions

- DiskMule commit: `72cf6d0f27f4729ffaf8a056fa819a2e82729cc6`
- Date: 2026-08-18
- Hardware: MacBook Pro `Mac16,6`, Apple M4 Max, 16 CPU cores, 128 GB unified memory
- OS: macOS 26.5.1 (`25F80`)
- Model: Ollama `gemma4:26b`, GGUF digest
  `7121486771cbfe218851513210c40b35dbdee93ab1ef43fe36283c883980f0df`
- Container: 17,987,569,344-byte GGUF v3, advertised Q4_K_M
- Prompt: raw BOS token only
- Decode: greedy/temperature zero, four requested output tokens, eight-token context limit
- State: warm filesystem state; OS caches were not flushed
- Command: `cargo test --release --test gemma4_metal_reference -- --ignored --nocapture`
- Process measurement: `/usr/bin/time -l` wrapped the complete oracle harness, which
  includes CPU, mapped-Metal, and forced-streamed model instances
- Thermal and power state were not controlled or measured

The host already had compressor history before the run. The measured process
reported zero swaps during the harness. Peak RSS for the complete three-model
test process was 2,884,698,112 bytes; this is not a per-backend resident-memory
measurement. `time -l` also reported a 36,323,832-byte peak physical-footprint
field, whose treatment of file mappings differs from RSS.

## Warm forced-streaming result

Configuration: one reusable expert slot per layer, which is deliberately too
small for Gemma's top-8 routed selection.

- Time to first token: 380.198 ms
- One-token prefill: 378.647 ms, approximately 2.64 prompt tokens/s
- Three subsequent decode forwards: 1.072 s, approximately 2.80 tokens/s
- Four-token total: 1.454 s
- Expert cache hits: 2
- Expert cache misses: 958, or 239.5 misses per forward token
- Evictions: 928
- Positional reads: 1,916, or 479 reads per forward token
- Explicit bytes read: 3,774,611,456, or 943.65 MB per forward token
- Aggregate measured I/O wait: 136.151 ms
- Logical expert-slot residency: 118,204,416 bytes
- Resident KV allocation at context 8: 3,604,480 bytes
- Non-expert mapped bytes touched: 6,594,168,312

The apparent read rate is dominated by warm OS cache and must not be presented
as SSD throughput. A true cold-storage study requires an isolated procedure and
must compare buffered and cache-bypassing reads one variable at a time.
