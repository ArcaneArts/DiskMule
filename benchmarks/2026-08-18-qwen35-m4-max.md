## Correctness result

DiskMule and Ollama selected the same four greedy token IDs:

```text
11, 353, 2688, 264
```

DiskMule decoded them as `, I'm a`. The installed tokenizer also matches
`llama-tokenize` on ASCII, contractions, numeric runs, newlines, special-token
framing, and Unicode byte sequences. The result exercises the hybrid recurrent
delta-rule and full-attention schedule, not a dense Transformer substitute.

The crucial reference detail is cyclic recurrent key-head mapping
`value_head % key_heads`; contiguous grouped-query repetition produced finite
but incorrect logits and failed this token oracle.

## User-facing oracle

With one greedy chat token, both real paths returned `Hello` for user message
`Hi` using the architecture's non-thinking chat envelope:

```text
DISKMULE_MAX_TOKENS=1 DISKMULE_TEMPERATURE=0 \
  cargo run --quiet -- run qwen3.8:latest

curl http://127.0.0.1:11435/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8:latest","messages":[{"role":"user","content":"Hi"}],"stream":false,"options":{"temperature":0,"num_predict":1}}'
```

Ollama 0.32.14 returned the same `Hello` content for the equivalent local chat
request with thinking disabled. These live checks validate integration; the
pinned token test above remains the stronger repeatable graph oracle.
